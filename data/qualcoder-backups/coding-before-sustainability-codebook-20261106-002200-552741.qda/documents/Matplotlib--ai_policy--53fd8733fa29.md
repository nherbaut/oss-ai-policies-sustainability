# Contributing guide<a href="#contributing-guide" class="headerlink"
title="Link to this heading">#</a>

You've discovered a bug or something else you want to change in
Matplotlib — excellent!

You've worked out a way to fix it — even better!

You want to tell us about it — best of all!

Below, you can find a number of ways to contribute, and how to connect
with the Matplotlib community.

<div class="sd-summary-content sd-card-body docutils">

Here are a few typical new contributor profiles. If you don't fit into
one of them, come talk to us on
<a href="https://discourse.matplotlib.org/"
class="reference external">Discourse</a> about how you might contribute.

- **You are a Matplotlib user, and you see a bug, a potential
  improvement, or something that annoys you, and you can fix it.**

  You can search our
  <a href="https://github.com/matplotlib/matplotlib/issues"
  class="reference external">issue tracker</a> for an existing issue
  that describes your problem or open a new issue to inform us of the
  problem you observed and discuss the best approach to fix it. If your
  contributions would not be captured on GitHub (social media,
  communication, educational content), you can also reach out to us on
  <a href="https://discourse.matplotlib.org/"
  class="reference external">Discourse</a> or attend any of our
  <a href="https://scientific-python.org/calendars"
  class="reference external">community meetings</a>.

- **You are not a regular Matplotlib user but a domain expert: you know
  about visualization, 3D plotting, design, technical writing,
  statistics, or some other field where Matplotlib could be improved.**

  Awesome — you have a focus on a specific application and domain and
  can start there. In this case, maintainers can help you figure out the
  best implementation;
  <a href="https://github.com/matplotlib/matplotlib/issues/new/choose"
  class="reference external">open an issue</a> in our issue tracker, and
  we'll be happy to discuss technical approaches.

  If you can implement the solution yourself, even better! Consider
  contributing the change as a
  <a href="#how-to-pull-request" class="reference internal"><span
  class="std std-ref">pull request</span></a> right away.

- **You are new to Matplotlib, both as a user and contributor, and want
  to start contributing but have yet to develop a particular interest.**

  Having some previous experience or relationship with the library can
  be very helpful when making open-source contributions. It helps you
  understand why things are the way they are and how they *should* be.
  Having first-hand experience and context is valuable both for what you
  can bring to the conversation (and given the breadth of Matplotlib's
  usage, there is a good chance it is a unique context in any given
  conversation) and make it easier to understand where other people are
  coming from.

  Understanding the entire codebase is a long-term project, and nobody
  expects you to do this right away. Start by building your experience
  in using Matplotlib: make complicated visualizations, use niche
  features, dive deep into one part of the library. This will help you
  build the context to then look at the existing issues and pull
  requests. You can then reach out to us at the
  <a href="#new-contributors" class="reference internal"><span
  class="std std-ref">new contributor</span></a> meeting or Discourse
  channel (incubator) to discuss what you would like to work on.

</div>

### Code<a href="#code" class="headerlink" title="Link to this heading">#</a>

You want to implement a feature or fix a bug or help with maintenance -
much appreciated! Our library source code is found in:

- Python library code: <span class="pre">`lib/`</span>

- C-extension code: <span class="pre">`src/`</span>

- Tests: <span class="pre">`lib/matplotlib/tests/`</span>

Because many people use and work on Matplotlib, we have guidelines for
keeping our code consistent and mitigating the impact of changes.

- <a href="coding_guide.html#coding-guidelines"
  class="reference internal"><span class="std std-ref">Coding
  guidelines</span></a>

- <a href="api_changes.html#api-changes" class="reference internal"><span
  class="std std-ref">API guidelines</span></a>

- <a href="pr_guide.html#pr-guidelines" class="reference internal"><span
  class="std std-ref">Pull request guidelines</span></a>

Code is contributed through pull requests, so we recommend that you
start at <a href="#how-to-pull-request" class="reference internal"><span
class="std std-ref">Start a pull request</span></a> If you get stuck,
please reach out on the
<a href="#contributor-incubator" class="reference internal"><span
class="std std-ref">Contributor incubator</span></a>

### Triage<a href="#triage" class="headerlink" title="Link to this heading">#</a>

We appreciate your help keeping the
<a href="https://github.com/matplotlib/matplotlib/issues"
class="reference external">issue tracker</a> organized because it is our
centralized location for feature requests, bug reports, tracking major
projects, and discussing priorities. Some examples of what we mean by
triage are:

- labeling issues and pull requests

- verifying bug reports

- debugging and resolving issues

- linking to related issues, discussion, and external work

Our triage process is discussed in detail in
<a href="triage.html#bug-triaging" class="reference internal"><span
class="std std-ref">Bug triage and issue curation</span></a>.

If you have any questions about the process, please reach out on the
<a href="#contributor-incubator" class="reference internal"><span
class="std std-ref">Contributor incubator</span></a>.

### Community<a href="#community" class="headerlink"
title="Link to this heading">#</a>

Matplotlib's community is built by its members, if you would like to
help out see our
<a href="communication_guide.html#communications-guidelines"
class="reference internal"><span class="std std-ref">Community
management guide</span></a>.

It helps us if you spread the word: reference the project from your blog
and articles or link to it from your website!

If Matplotlib contributes to a project that leads to a scientific
publication, please cite us following the
<a href="../project/citing.html" class="reference internal"><span
class="doc">Citing Matplotlib</span></a> guidelines.

If you have developed an extension to Matplotlib, please consider adding
it to our <a href="https://github.com/matplotlib/mpl-third-party"
class="reference external">third party package</a> list.

tool, the resulting contribution is the responsibility of the human
contributor. We expect dedicated and authentic engagement in our
community. In particular when using AI, carefully consider what and how
to communicate, question results, think things through thoroughly and
make well-informed decisions.

## New contributors<a href="#new-contributors" class="headerlink"
title="Link to this heading">#</a>

Everyone comes to the project from a different place — in terms of
experience and interest — so there is no one-size-fits-all path to
getting involved. We recommend looking at existing issue or pull request
discussions, and following the conversations during pull request reviews
to get context. Or you can deep-dive into a subset of the code-base to
understand what is going on.

<div id="new-contributors-meeting" class="section">

<span id="id2"></span>

### New contributors meeting<a href="#new-contributors-meeting" class="headerlink"
title="Link to this heading">#</a>

Once a month, we host a meeting to discuss topics that interest new
contributors. Anyone can attend, present, or sit in and listen to the
call. Among our attendees are fellow new contributors, as well as
maintainers, and veteran contributors, who are keen to support
onboarding of new folks and share their experience. You can find our
community calendar link at the
<a href="https://scientific-python.org/calendars/"
class="reference external">Scientific Python website</a>, and you can
browse previous meeting notes on <a
href="https://github.com/matplotlib/ProjectManagement/tree/master/new_contributors_meeting"
class="reference external">GitHub</a>. We recommend joining the meeting
to clarify any doubts, or lingering questions you might have, and to get
to know a few of the people behind the GitHub handles 😉. You can reach
out to us on
<a href="https://discourse.matplotlib.org/chat/c/incubator/4"
class="reference external">incubator chat</a> for any clarifications or
suggestions. We ❤ feedback!

</div>

<span id="id3"></span>

### Contributor incubator<a href="#contributor-incubator" class="headerlink"
title="Link to this heading">#</a>

The incubator is our non-public communication channel for new
contributors. It is a public chat room on
<a href="https://discourse.matplotlib.org/"
class="reference external">Discourse</a> moderated by core Matplotlib
developers where you can get guidance and support for your first few
PRs. It's a place where you can ask questions about anything: how to use
git, GitHub, how our PR review process works, technical questions about
the code, what makes for good documentation or a blog post, how to get
involved in community work, or get a "pre-review" on your PR.

To join, go to <a href="https://discourse.matplotlib.org/"
class="reference external">Discourse</a> and click on the chat bubble
icon next to the search icon at the top right of the page. Then, find
the "Incubator" channel.

</div>

### Good first issues<a href="#good-first-issues" class="headerlink"
title="Link to this heading">#</a>

We have marked some issues as <a
href="https://github.com/matplotlib/matplotlib/issues?q=state%3Aopen%20label%3A%22%F0%9F%8C%B1%20Good%20first%20issue%22"
class="reference external">🌱 Good first issue</a> because we think they
are a good entry point into the process of contributing to Matplotlib.
These issues are well documented, do not require a deep understanding of
the internals of Matplotlib, and do not need urgent resolution. Good
first issues are intended to onboard newcomers with a genuine interest
in improving Matplotlib, in the hopes that they will continue to
participate in our development community; therefore, pull requests that
are <a href="#generative-ai" class="reference internal"><span
class="std std-ref">AI generated</span></a> will be closed.

<span id="first-contribution"></span>

### First contributions<a href="#first-contributions" class="headerlink"
title="Link to this heading">#</a>

If this is your first open source contribution, or your first time
contributing to Matplotlib, and you need help or guidance finding a good
first issue, look no further. This section will guide you through each
step:

1.  Navigate to the
    <a href="https://github.com/matplotlib/matplotlib/issues/"
    class="reference external">issues page</a>.

2.  Filter labels with <a
    href="https://github.com/matplotlib/matplotlib/labels/Difficulty%3A%20Easy"
    class="reference external">"Difficulty: Easy"</a> & <a
    href="https://github.com/matplotlib/matplotlib/issues?q=state%3Aopen%20label%3A%22%F0%9F%8C%B1%20Good%20first%20issue%22"
    class="reference external">"🌱 Good first Issue"</a> (optional).

3.  Click on an issue you would like to work on, and check to see if the
    issue has a pull request opened to resolve it.

    - A good way to judge if you chose a suitable issue is by asking
      yourself, "Can I independently submit a PR in a reasonable time
      frame?" This should (at most) be a few days for an easy issue. If
      it takes longer, let us know why.

    - If you are new to open source, we strongly recommend that you do
      not choose a complicated issue for your first contribution -
      please ask in the incubator channel if you need help gauging the
      complexity of the work.

4.  Check existing pull requests (e.g.,
    <a href="https://github.com/matplotlib/matplotlib/pull/28476/"
    class="reference external">PR #28476</a>) and filter by the issue
    number to make sure the issue is not in progress:

    - If the issue has a pull request (is in progress), tag the user
      working on the issue, and ask to collaborate (optional).

    - If there is no pull request,
      <a href="#how-to-pull-request" class="reference internal"><span
      class="std std-ref">create a new pull request</span></a>.

5.  Please familiarize yourself with the pull request template (see
    below), and ensure you understand/are able to complete the template
    when you open your pull request. Additional information can be found
    in the <a href="https://matplotlib.org/devdocs/devel/pr_guide.html"
    class="reference external">pull request guidelines</a>.

<div class="admonition important">

Important

Make sure you finish addressing any review comments on your first PR and
wait for it to be merged (or closed) before opening a new one. It can be
a valuable learning experience to go through the review process and to
get feedback on your contribution, while also helping maintainers spend
their time effectively.

<div id="choose-an-issue" class="section">

<span id="managing-issues-prs"></span>

## Choose an issue<a href="#choose-an-issue" class="headerlink"
title="Link to this heading">#</a>

In general, the Matplotlib project does not assign issues. Issues are
"assigned" or "claimed" by opening a PR; there is no other assignment
mechanism. If you have opened such a PR, please comment on the issue
thread to avoid duplication of work. Please check if there is an
existing PR for the issue you are addressing. If there is, try to work
with the author by submitting reviews of their code or commenting on the
PR rather than opening a new PR; duplicate PRs are subject to being
closed. However, if the existing PR is an outline, unlikely to work, or
stalled, and the original author is unresponsive, feel free to open a
new PR referencing the old one.

<div id="difficulty" class="section">

### Difficulty<a href="#difficulty" class="headerlink"
title="Link to this heading">#</a>

Issues may additionally be tagged with a difficulty.
<span class="pre">`Difficulty:`</span>` `<span class="pre">`Easy`</span>
is suitable for people with beginner scientific Python experience, i.e.
fluency with Python syntax and some experience using libraries like
Numpy, Pandas, or Xarray.
<span class="pre">`Difficulty:`</span>` `<span class="pre">`Medium`</span>
and
<span class="pre">`Difficulty:`</span>` `<span class="pre">`Hard`</span>
require more programming experience. This could be for a variety of
reasons, for example:

- requires understanding intermediate to advanced Python features, such
  as decorators, context managers, or meta-programming

- is in areas of the code base which have more interdependencies or is
  legacy code.

- involves complex or significant changes to algorithms or architecture.

Generally, the difficulty level is correlated with how much conceptual
(and contextual) understanding of Matplotlib is required to resolve it.

</div>

<div id="start-a-pull-request" class="section">

<span id="how-to-pull-request"></span>

## Start a pull request<a href="#start-a-pull-request" class="headerlink"
title="Link to this heading">#</a>

The preferred way to contribute to Matplotlib is to fork the
<a href="https://github.com/matplotlib/matplotlib/"
class="reference external">main repository</a> on GitHub, then submit a
"pull request" (PR). To work on a pull request:

1.  **First** set up a development environment, either by cloning a copy
    of the Matplotlib repository to your own computer or by using Github
    codespaces, by following the instructions in
    <a href="development_setup.html#installing-for-devs"
    class="reference internal"><span class="std std-ref">Development
    setup</span></a>

2.  **Then** start solving the issue, following the guidance in
    <a href="development_workflow.html#development-workflow"
    class="reference internal"><span class="std std-ref">development
    workflow</span></a>

3.  **As part of verifying your changes** check that your contribution
    meets the <a href="pr_guide.html#pr-author-guidelines"
    class="reference internal"><span class="std std-ref">pull request
    guidelines</span></a> and then
    <a href="development_workflow.html#open-pull-request"
    class="reference internal"><span class="std std-ref">open a pull
    request</span></a>.

4.  **Finally** follow up with maintainers on the PR if waiting more
    than a few days for feedback.
    <a href="development_workflow.html#update-pull-request"
    class="reference internal"><span class="std std-ref">Update the pull
    request</span></a> as needed.

If you have questions of any sort, reach out on the
<a href="#contributor-incubator" class="reference internal"><span
class="std std-ref">Contributor incubator</span></a> and join the
<a href="#new-contributors-meeting" class="reference internal"><span
class="std std-ref">New contributors meeting</span></a>.
